# D&D Mini 2.0

Новая самостоятельная версия Telegram RPG на Python, aiogram и SQLite.

**Статус:** разработка и тестирование.

Проект полностью отделён от старого `shpakdnd_bot`. Изменения не должны затрагивать production.

## Структура проекта

```text
/opt/mini2.0/
├── bot.py                   # Точка входа
├── requirements.txt         # Зависимости
├── src/
│   ├── main/                # Команды, создание героя и меню
│   ├── mainplayer/          # Герой, характеристики, пассивки, SQLite
│   ├── mechanics/           # Общие игровые механики (roll)
│   ├── characters/          # Коллекционные персонажи
│   ├── locations/           # Локации
│   ├── bosses/              # Боссы
│   └── items/               # Предметы
├── catalogs/
│   ├── menu/                # JSON-описания меню
│   └── mainplayer/          # Каталоги рас, классов и пассивок
└── tests/                   # Автоматические тесты
```

## Реализованные игровые механики

### Броски кубиков (roll)

Базовая механика находится в `src/mechanics/roll.py`.

Поддерживаются кубики D&D: `d4`, `d6`, `d8`, `d10`, `d12`, `d20`, `d100`.

```python
from src.mechanics.roll import roll

result = roll(20)                    # 1d20
result = roll(6, count=3)           # 3d6
result = roll(6, count=3, modifier=2)  # 3d6+2

result.rolls    # Результаты отдельных кубиков
result.total    # Сумма с модификатором
```

Максимальное количество кубиков за вызов — 100. Механика не зависит от Telegram и SQLite.

### Характеристики героя

В `src/mainplayer/model.py` герой содержит шесть базовых характеристик:

| Характеристика | ID |
|---|---|
| Сила | `strength` |
| Ловкость | `dexterity` |
| Телосложение | `constitution` |
| Интеллект | `intelligence` |
| Мудрость | `wisdom` |
| Харизма | `charisma` |

При создании героя все базовые характеристики равны `0`.

- `player.stats` — базовые характеристики.
- `player.passives` — список ID активных пассивок.
- `player.effective_stats` — итоговые характеристики с бонусами.

Итоговое значение вычисляется по формуле:

`Базовая характеристика + сумма бонусов активных пассивок`

Расчёт выполняется в `src/mainplayer/attributes.py`. Итоговые значения отдельно в базе не хранятся.

### Система пассивок

Определения пассивок находятся в `catalogs/mainplayer/passives.json`.

Каждая пассивка имеет стабильный ID, название и набор бонусов:

```json
{
  "elf_passive": {
    "name": "Эльф",
    "stats": {
      "dexterity": 2
    }
  }
}
```

У героя хранятся только ID активных пассивок. Одну и ту же пассивку нельзя добавить повторно.

Управление выполняется функциями из `src/mainplayer/storage.py`:

- `add_passive()` — добавить пассивку.
- `remove_passive()` — удалить пассивку.
- `set_base_stat()` — изменить базовую характеристику.

Бонусы пересчитываются при обращении к `player.effective_stats`. Добавление или удаление пассивки не изменяет базовые характеристики.

### Создание персонажа

Регистрация реализована в `src/main/creation.py`.

Последовательность создания героя:

1. Ввод имени через `/create Имя` или `/create "Имя"`.
2. Создание записи героя и назначение `lvl1up`.
3. Выбор расы и автоматическое назначение расовой пассивки.
4. Выбор класса и автоматическое назначение классовой пассивки.
5. Переход в главное меню героя.

Также поддерживаются имена в кавычках `«»` и `“”`.

Связь расы или класса с пассивкой задаётся полем `passive` в соответствующем JSON-каталоге.

Пример для эльфа-волшебника:

```json
["lvl1up", "elf_passive", "wizard_passive"]
```

Выбор расы или класса и добавление связанной пассивки выполняются одной транзакцией SQLite.

Пассивка `lvl4up` уже определена в каталоге, но автоматическое назначение при повышении уровня пока не реализовано.

## Тестирование

| Команда | Назначение |
|---|---|
| `mitest all` | Все тесты — основная проверка |
| `mitest menus` | Тесты меню |
| `mitest creation` | Тесты создания персонажа |
| `mitest creation_handlers` | Тесты Telegram-обработчиков регистрации |
| `mitest mainplayer` | Тесты модели главного персонажа |


Дополнительные тесты новых механик:

```bash
cd /opt/mini2.0

.venv/bin/python -m unittest discover -s tests -p "test_roll.py" -v
.venv/bin/python -m unittest discover -s tests -p "test_attributes.py" -v
```

Полная проверка перед коммитом:

```bash
mitest all
.venv/bin/python -m compileall -q bot.py src tests
```

Тесты проверяют броски кубиков, расчёт характеристик, добавление и удаление пассивок, назначение расы и класса, миграцию SQLite и обработчики регистрации.

Проверка синтаксиса:

```bash
cd /opt/mini2.0
.venv/bin/python -m compileall -q bot.py src
```

## Порядок внесения изменений

1. Изменить код.
2. Выполнить `mitest all`.
3. Проверить синтаксис через `compileall`.
4. При успешных проверках выполнить `mini restart`.
5. Проверить работу в Telegram и журнал.
6. Сохранить изменения в Git.

Изменения Python-кода требуют перезапуска процесса.

JSON-каталоги загружаются при обращении, поэтому корректные изменения содержимого обычно применяются без перезапуска.


## Git и утилита migit

Для Git-операций используется серверная утилита `migit`.

Предполагаемый путь: `/srv/mini_utl/utls/migit`.

Утилита работает с репозиторием `/opt/mini2.0` от пользователя `shpakbot`, избавляя от необходимости каждый раз указывать `sudo -u shpakbot -H`.

### Основные команды

| Команда | Назначение |
|---|---|
| `migit status` | Состояние репозитория |
| `migit diff` | Изменения до и после индексации |
| `migit check` | Статус и diff |
| `migit add .` | Добавить все изменения |
| `migit add README.md` | Добавить конкретный файл |
| `migit "Описание"` | Создать коммит |
| `migit push` | Отправить изменения в GitHub |
| `migit pull` | Получить изменения без merge-коммита |
| `migit branch` | Показать ветки |
| `migit branch "имя"` | Переключиться на ветку или создать её |

### Обычный порядок работы

```bash
mitest all
migit check
migit add .
migit check
migit "Описание изменений"
migit push
```

Перед коммитом необходимо проверять список добавленных файлов.

`migit add .` не гарантирует исключение секретов: нельзя отправлять токены, конфигурации с паролями, базы данных, ключи, резервные копии и пользовательские данные.

### Работа с ветками

```bash
migit branch
migit branch "feature/battle"
migit branch main
```

Если ветка существует локально, утилита переключается на неё. Если она существует только в `origin`, создаётся отслеживающая локальная ветка. Если ветки нет, она создаётся локально.

Новая ветка отправляется командой `migit push`.

Утилиты `migit`, `mitest` и `mini` размещаются вне Git-репозитория и не входят в GitHub-код проекта.

Git push не выполняет автоматический перезапуск бота.


## База данных

SQLite хранит состояние главного героя в таблице `players`:

- `id` — идентификатор игрока.
- `name` — имя героя.
- `race` — ID выбранной расы.
- `class_name` — ID выбранного класса.
- `level` — уровень героя.
- `stats` — базовые характеристики в JSON.
- `passives` — массив ID активных пассивок в JSON.

У новых персонажей базовые характеристики равны `0`, а пассивка `lvl1up` выдаётся автоматически.

Пассивки, назначаемые расой и классом, добавляются при выборе соответствующей сущности.

Итоговые характеристики вычисляются динамически и не дублируются в SQLite.

### Миграции

`init_db()` создаёт таблицу при отсутствии, но не обновляет структуру уже существующей таблицы.

Для добавления колонок `stats` и `passives` предусмотрена функция `migrate_player_stats()` в `src/mainplayer/storage.py`.

Перед миграцией действующей БД обязательно создать резервную копию.

Миграция структуры не назначает автоматически пассивки старым персонажам и не пересчитывает их характеристики. Перенос существующих персонажей выполняется отдельно.

Запрещено удалять или пересоздавать действующую базу ради исправления ошибок.

## Правила разработки

- Один JSON-файл — одно меню.
- Один Python-обработчик — одна группа меню.
- Игровая логика находится в `src/`.
- Названия и характеристики игровых сущностей находятся в каталогах.
- Персональные меню не должны быть видны другим игрокам.
- Перед запуском новой версии обязательны тесты.
- Без отдельного согласования не изменять production.
- Не выполнять автоматическое развёртывание только из-за Git push.
