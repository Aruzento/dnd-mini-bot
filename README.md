# D&D Mini 2.0

Новая самостоятельная версия Telegram RPG на Python, aiogram и SQLite.

**Статус:** разработка и тестирование.

Проект полностью отделён от старого `shpakdnd_bot`. Изменения не должны затрагивать production.

## Структура проекта

```text
/opt/mini2.0/
├── bot.py                   # Точка входа
├── requirements.txt         # Зависимости
├── src/
│   ├── main/                # Команды и обработчики меню
│   ├── mainplayer/          # Модель игрока и SQLite
│   ├── characters/          # Коллекционные персонажи
│   ├── locations/           # Локации
│   ├── bosses/              # Боссы
│   └── items/               # Предметы
├── catalogs/
│   ├── menu/                # Один JSON = одно меню
│   └── mainplayer/          # Справочники рас и классов
└── tests/                   # Автоматические тесты
```

## Тестовое окружение

- Сервер: `VM-338333`
- Проект: `/opt/mini2.0`
- Служба systemd: `mini2.service`
- Пользователь службы: `shpakbot`
- Python: `/opt/mini2.0/.venv/bin/python`
- Конфигурация: `/srv/mini_utl/access_utl/bot.env`
- SQLite: `/srv/mini_utl/db/mini.db`
- Резервные копии: `/srv/mini_utl/db-backups/`
- Утилиты: `/srv/mini_utl/utls/`

Токены и данные пользователей в Git не хранятся.

## Управление ботом

Команды запускаются на тестовом сервере с необходимыми правами:

| Команда | Назначение |
|---|---|
| `mini start` | Запустить бота |
| `mini stop` | Остановить бота |
| `mini restart` | Перезапустить бота |
| `mini status` | Проверить состояние |
| `mini logs` | Посмотреть последние записи журнала |

Дополнительная диагностика:

```bash
journalctl -u mini2.service -f
systemctl status mini2.service --no-pager
```

## Тестирование

| Команда | Назначение |
|---|---|
| `mitest all` | Все тесты — основная проверка |
| `mitest menus` | Тесты меню |
| `mitest creation` | Тесты создания персонажа |
| `mitest creation_handlers` | Тесты Telegram-обработчиков регистрации |
| `mitest mainplayer` | Тесты модели главного персонажа |

Проверка синтаксиса:

```bash
cd /opt/mini2.0
.venv/bin/python -m compileall -q bot.py src
```

## Порядок внесения изменений

1. Изменить код.
2. Выполнить `mitest all`.
3. Проверить синтаксис через `compileall`.
4. При успешных проверках выполнить `mini restart`.
5. Проверить работу в Telegram и журнал.
6. Сохранить изменения в Git.

Изменения Python-кода требуют перезапуска процесса.

JSON-каталоги загружаются при обращении, поэтому корректные изменения содержимого обычно применяются без перезапуска.

## Команды Git

Проверка изменений:

```bash
git status
git diff
```

Сохранение изменений:

```bash
git add src catalogs tests bot.py README.md requirements.txt
git commit -m "Описание изменений"
```

Отправка в GitHub:

```bash
git push
```

Получение обновлений:

```bash
git pull --ff-only
```

История коммитов:

```bash
git log --oneline -10
```

Перед каждым коммитом проверять, что в индекс не попали токены, базы данных и временные файлы.

## База данных

SQLite хранит состояние игроков, включая имя, расу, класс и уровень.

Изменения структуры базы выполнять через контролируемые миграции с резервной копией.

Нельзя удалять или пересоздавать рабочую базу ради обновления кода.

## Правила разработки

- Один JSON-файл — одно меню.
- Один Python-обработчик — одна группа меню.
- Игровая логика находится в `src/`.
- Названия и характеристики игровых сущностей находятся в каталогах.
- Персональные меню не должны быть видны другим игрокам.
- Перед запуском новой версии обязательны тесты.
- Без отдельного согласования не изменять production.
- Не выполнять автоматическое развёртывание только из-за Git push.
